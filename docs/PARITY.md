# Parity with the web version

Each DSP piece is ported from the TypeScript code in
[Powelus/pow-daw](https://github.com/Powelus/pow-daw) and must reproduce what the
original produces. The tests hold numbers generated by the original.

## Making test numbers

In a checkout of the web repository (Node 22.6 or newer runs TypeScript files
that have no enums directly):

```sh
cat > /tmp/gold.mjs <<'JS'
import { biquadDb } from './src/audio/dsp/biquad.ts';
console.log(biquadDb('lowpass', 1000, 0, 0.707, 1000).toFixed(9));
JS
node --experimental-strip-types /tmp/gold.mjs
```

Paste the printed values into a table in the Rust test, with a comment that says
where they came from. Pick points away from exact zeros (a notch right at its
centre is numerically fragile).

## Larger pieces

Engines (Facet, Mist and the wavetable engine) are checked by rendering the same
patch and notes in both versions and comparing the audio sample by sample, within
a small tolerance. The cases live in `tools/parity/*.cases.json` and the
generators in `tools/parity/*.gen.test.ts` (each file says how to run it from a
checkout of the web repository). The reference audio is committed under
`crates/las-dsp/tests/fixtures/`.

Status: Facet (5 cases), Mist (5 cases, plus the built-in texture), the
wavetable synth (11 cases), the effects (19 cases) and the loudness meter match
with zero difference (the meter to 1e-9). The 23 wavetables match to
1e-17 (rounding to `f32`).

The effects the web version builds from Web Audio nodes (EQ, overdrive, chorus,
phaser, auto filter, stereo tool, maximizer, convolution reverb) have no sample
exact reference, since Web Audio does not specify them. They are tested for
their behaviour instead: filter responses against the biquad formulas, the wave
shaper curve, the convolver's normalisation, and level and stability checks.

Projects: `tools/project/project.gen.test.ts` makes the demo song as JSON and as
`.las` files (encrypted and plain, with a sample), and a damaged version 1
project with the web version's repair of it. `las-project` reads the files to the
same project, and repairs the damaged one with the same result and the same
notes in the same order (ids that the repair makes up are random on both sides
and are not compared). The generator can also read a file written by Rust to
check the other direction.

Mixing: `tools/project/mix.gen.test.ts` makes small projects (every synth, the
arpeggiator, an effects rack, sends, sidechain, delay compensation, each effect
Chromium builds from Web Audio nodes) and `tools/project/render-web.mjs` renders
them with the web version in headless Chromium. The reference audio is committed
under `crates/las-engine/tests/fixtures/` and `crates/las-engine/tests/web_parity.rs`
compares. The instruments, mixer and scheduler agree to rounding; the Web Audio
based effects agree to better than 85 dB below the signal (the browser is the
reference for them, since Web Audio does not specify them).

The synth worklet needs browser globals; `tools/parity/synth.gen.test.ts` supplies
them and fixes `Math.random`. The original is not seeded, so its cases leave out
random phase, noise, sample and hold, and the `rand` source.

## Tolerances

- Pure math (filters, curves): 1e-6 in dB.
- Rendered audio with the same random seed: 1e-4 per sample.
- Anything with unseeded randomness: compare levels and spectra, not samples.
