# Parity with the web version

Each DSP piece is ported from the TypeScript code in
[Powelus/pow-daw](https://github.com/Powelus/pow-daw) and must reproduce what the
original produces. The tests hold numbers generated by the original.

## Making test numbers

In a checkout of the web repository (Node 22.6 or newer runs TypeScript files
that have no enums directly):

```sh
cat > /tmp/gold.mjs <<'JS'
import { biquadDb } from './src/audio/dsp/biquad.ts';
console.log(biquadDb('lowpass', 1000, 0, 0.707, 1000).toFixed(9));
JS
node --experimental-strip-types /tmp/gold.mjs
```

Paste the printed values into a table in the Rust test, with a comment that says
where they came from. Pick points away from exact zeros (a notch right at its
centre is numerically fragile).

## Larger pieces

Engines (Facet, Mist and the wavetable engine) are checked by rendering the same
patch and notes in both versions and comparing the audio sample by sample, within
a small tolerance. The web version has the reference render helpers in
`tests/engines.test.ts`.

## Tolerances

- Pure math (filters, curves): 1e-6 in dB.
- Rendered audio with the same random seed: 1e-4 per sample.
- Anything with unseeded randomness: compare levels and spectra, not samples.
